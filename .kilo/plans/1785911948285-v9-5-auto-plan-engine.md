# Auto-Plan v9.5 — Implementation Plan (draft, refining)

## Context

`DienstplanRAD` is a rule-based monthly planner for radiology standby duty (BD = Bereitschaftsdienst, HG = Hintergrunddienst, RBN = neuroradiological call).
v9 ("Hybrid Exact Observatory") already loads a real CP-SAT core in the browser via CDN
(`auto-planner-v9.js` imports `buildCpSatModel` / `solveCpSatModel` from `js/auto-plan-cp-sat.js`;
Solver-Load-Order in `auto-plan-cp-sat.js:38-42` → `or-tools-wasm@0.9.1` then `cpsat-js@1.3.0` over jsdelivr `+esm`).
`_headers` already ships `Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp`, so the
multithreaded WASM build works. Pipeline: `analysis → model → exact → rescue → repair → perfect → audit → certify`.

**Gaps found (basis for v9.5):**
1. **Partial model coverage.** The CP-SAT model encodes exclusivity, rest (Ruhezeit) and R13 (HG-vor-BD werktags)
   (`auto-plan-cp-sat.js:346,358,371`), but **M1 (CT-Leitung), Becker-FZA, and v4.10 (Fr-BD/Sa-frei/So-BD)** are only caught
   post-hoc by the rule-engine audit, not enforced in-model → exact core can return plans the audit then rejects.
2. **Fake explainability.** `RELAX_GROUPS` + greedy re-enable (`auto-plan-cp-sat.js:53-`, fallback at `auto-planner-v9.js:468`)
   is a heuristic, NOT a true UNSAT-core / MUS / MCS. No real conflict explanation for the Studio.
3. **No minimal perturbation.** Re-planning wipes manual edits; baseline is only a hint, not a protected objective.
4. **Shallow Studio settings** vs. what an exact engine can expose.
5. **Layout risk** of overlaps in the Auto-Plan Studio modal on small/medium screens.

## Decisions (locked)

- **Keep the CP-SAT hybrid.** Live, free, browser-side — aligned with constraints. Do not replace.
- **Vendor the solver locally.** Commit `or-tools-wasm` (portable threaded build) and `cpsat-js` (single-threaded portable
  build) under `vendor/`. `SOLVER_LOAD_ORDER` (`auto-plan-cp-sat.js:38`) → local-first, CDN fallback. `_headers` already grants
  `/vendor/*` `immutable` cache; fits the 25 MiB Pages asset limit.
- **Close model coverage:** encode M1, Becker-FZA, v4.10 as constraints in `buildCpSatModel` (mirror R13/rest style).
- **Real explainability:** CP-SAT assumptions API (`model.AddAssumption`) for a true UNSAT-core / MUS on INFEASIBLE; map core
  to `RELAX_GROUPS`; present human-readable conflicts. Greedy relaxation = last resort only.
- **Leximin fairness** stays first objective phase; configurable fairness weight + soft slack via `RELAX_GROUPS`.
- **Minimal perturbation:** baseline change-penalty objective so manual edits are preserved (Studio toggle, default on).
- **Studio settings + layout hardening** as detailed below.
- **Release token bump** `20260803.4` → new token in the 4 lockstep locations.

## Model encoding sketches (buildCpSatModel)

Slot variables: `bd[d,p]`, `hg[d,p]` ∈ {0,1}, `exclusive` (person not both same day), `rest` (Ruhezeit), `hgBeforeBd` (R13) already present.

- **M1 — CT-Leitung availability.** Confirm exact semantics from the rule catalog (`grep -n "M1\|Leitung" js/rules*.js`).
  Sketch: derive per-day `availableForLeadership[d,p] = eligible(p,d) ∧ ¬absent(p,d) ∧ ¬beckerFza(d,p)`; add
  `sum_{p qualified} coverage(d,p) ≥ 1` per relevant day/period (hard, `qualification`/`availability` group). Becker-FZA days
  count as absence (per spec:127). *Implementer must reconcile the precise M1 wording with the catalog before encoding.*
- **Becker-FZA (CORRECTED per user).** Rule: Becker derives an FZA after a BD on **regular weekdays AND Saturday**
  (user clarification widens `Eignungsregeln.txt:125-126`, which restricts FZA derivation to Samstags-BD — **flag: reconcile
  spec vs. runtime behavior**). Encode with reified coupling:
  `fzaBecker[next(d)] ⇔ bd[d,becker]` for each Becker-BD day `d`; on `next(d)` (next regular workday) forbid
  `bd[next,becker]` and `hg[next,becker]` (FZA ⇒ absent), and feed `beckerFza(day)` into M1 absence + exclude Becker from
  fairness comparison.
- **v4.10 — Wochenendkette (Fr-BD · Sa frei · So-BD).** For each person `p` and Fri `d` with weekend Sat/Sun:
  `chain_p = bd[fri,d,p] ∧ ¬(bd[sat]+hg[sat]+rbn[sat]+rbn2[sat])[p] ∧ bd[sun,d+2,p]`.
  Spec marks both BD cells **rot / besonders bestätigungspflichtig** → model as **high-penalty soft** (rot tier) in the
  `coupling` relaxable group, NOT a hard block (preserves current "confirmable" behavior, symmetric by construction).

Hard vs. soft mapping (severity ladder grau<0 / grün0 / gelb1 / orange2 / rot3):
gray + red ⇒ hard constraints; orange/yellow ⇒ soft penalties in `RELAX_GROUPS`; rot (v4.10) ⇒ high soft penalty.

## Studio settings & layout detail

**New controls (auto-plan-studio-v9.js + defaults.js; persisted via functions/api/settings.js):**
- Solver backend: `auto` / `cp-sat-exact` / `cp-sat-lns` / `heuristic` (v8.5).
- Fairness weight: slider (low…high) → drives leximin first-phase strength.
- Relaxation depth: `shallow` / `deep` (how many `RELAX_GROUPS` tiers the MUS may relax).
- Time/effort budget: `Standard` / `Tief` / `Maximum` (maps to existing search-intensity + LNS rounds).
- Per-`RELAX_GROUPS` toggles: qualification, availability, sequence, limits, coupling, coverage.
- Minimal-perturbation protect: toggle (default on when baseline present).
- MUS auto-relax: toggle (apply minimal relaxation automatically vs. only show conflict).

**Layout hardening (auto-plan-studio-v9.css):**
- Modal body ⇒ scrollable, sectioned flex/grid with sticky footer for result/adoption controls.
- Sections: Solver · Ziele & Fairness · Regel-Relaxation · Stabilität · Budget.
- Responsive breakpoints 360 / 768 / 1280px; guarantee no overlap/occlusion; all controls always reachable;
  keep result table and "Übernehmen" visible (sticky footer). Remove any fixed-height overflow that clips content.
